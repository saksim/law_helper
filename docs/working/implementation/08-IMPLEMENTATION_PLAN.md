# 08 IMPLEMENTATION_PLAN：阶段实施计划

## 1. 目标

把平台蓝图推进为 P0 试点可用版，周期建议 10-14 周。施工原则：先闭环，再增强；先授权 API，再自动化页面；先人工复核，再模型优化；先结构和审计，再体验细节扩展。

## 2. 团队配置

| 角色 | 投入 | 职责 |
|---|---:|---|
| 产品/项目负责人 | 1 | 需求、样本、验收、律师沟通 |
| 后端/平台工程师 | 1 | API、权限、插件、任务、审计、数据模型 |
| AI/NLP 工程师 | 1 | OCR、抽取、评分、报告、评估 |
| 前端工程师 | 1 | Web 工作台、移动 H5、报告与复核 |
| 数据工程师 | 0.5 | 数据源、清洗、索引、监控数据 |
| QA | 0.5 | 测试矩阵、回归集、上线门禁 |
| 法律业务专家 | 0.3-0.5 | 模板、线索价值、复核标准 |

## 3. 阶段计划

### Phase 0：样本驱动设计，1-2 周

交付：

- 10 份 PDF 样本。
- 5 个执行案件样本。
- 数据源授权确认。
- 字段字典初版。
- 桌面和移动核心原型。
- P0 验收集。

退出标准：PRD、UX、数据字典、QA 验收计划冻结到可开发状态。

### Phase 1：平台内核与文档链路，2-3 周

交付：

- 用户、角色、案件、文件基础模型。
- 文件上传与对象存储。
- 文档解析任务队列。
- Markdown/JSON/坐标映射输出。
- 审计日志基础。
- 桌面案件工作台雏形。

退出标准：真实 PDF 可上传、解析、查看、校对。

### Phase 2：主体与线索链路，3-4 周

交付：

- 主体识别与候选确认。
- 2 到 3 个数据连接器。
- external_records 规范化。
- 财产线索抽取与去重。
- 线索评分和报告模板。
- 报告复核状态。

退出标准：5 个执行案件样本能生成可复核财产线索报告。

### Phase 3：监控通知与移动轻操作，2-3 周

交付：

- 监控主体配置。
- 定时任务和快照。
- 字段 Diff 和事件分类。
- 飞书/企微/邮件/站内通知。
- 移动 H5 提醒详情。
- 确认/忽略/转任务。

退出标准：监控事件能推送到手机并完成 3 步处理。

### Phase 4：安全、质量与试点上线，2 周

交付：

- 数据分级策略。
- 模型网关策略。
- 权限和越权测试。
- E2E 回归集。
- 律师可用性测试。
- Runbook 和回滚演练。

退出标准：QA 门禁通过，试点用户确认可用。

## 4. Sprint 拆解

| Sprint | 目标 | 主要产出 |
|---|---|---|
| S0 | 施工准备 | 样本、原型、字段、验收集 |
| S1 | 案件与文件 | 案件、上传、存储、审计 |
| S2 | 文档解析 | OCR/解析、Markdown/JSON、校对 |
| S3 | 主体与数据源 | 主体消歧、连接器、外部记录 |
| S4 | 线索报告 | 线索抽取、评分、报告、复核 |
| S5 | 监控通知 | 快照、Diff、通知、移动详情 |
| S6 | 安全与上线 | 权限、模型策略、QA、Runbook |

## 5. 依赖关系

```text
PRD/UX/DATA -> API/PLUGIN/SECURITY -> 开发 -> QA -> Runbook -> 试点上线
```

关键依赖：

- 没有样本，不能验证 OCR 和线索报告。
- 没有数据源授权，不能承诺连接器能力。
- 没有数据分级，不能开放模型调用。
- 没有 UX 原型，前端会按技术模块误建页面。

## 6. 里程碑

| 里程碑 | 验收 |
|---|---|
| M1 样本和原型冻结 | 产品、律师、研发确认 P0 主流程 |
| M2 文档链路可跑通 | PDF 上传到校对闭环 |
| M3 线索报告可复核 | 5 个案件生成报告 |
| M4 移动提醒闭环 | 手机处理提醒并转任务 |
| M5 试点上线 | QA、安全、可用性门禁通过 |

## 7. 风险控制

| 风险 | 预案 |
|---|---|
| 数据源授权延迟 | 先使用人工补录和模拟连接器 |
| OCR 样本质量差 | 标注低置信度，缩小承诺范围 |
| 主体消歧不稳定 | 引入人工确认候选主体 |
| 提醒噪声过高 | 增加忽略/重复反馈，先低频推送 |
| 律师不愿使用 | 先做真实用户可用性测试和文案调整 |

## 8. 交接对象

- 给研发负责人：Sprint 和依赖管理。
- 给产品负责人：样本和验收推进。
- 给 QA：阶段门禁和试点风险。
- 给交付：上线计划和客户沟通节奏。
