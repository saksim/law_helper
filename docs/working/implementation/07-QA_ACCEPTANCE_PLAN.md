# 07 QA_ACCEPTANCE_PLAN：质量与验收计划

## 1. 风险等级

P0 风险等级：P1。

原因：平台处理法律案件材料和执行线索，涉及客户敏感信息、法律责任、数据源合规和律师真实使用体验。禁止无来源、无审计、无复核上线。

## 2. 验收范围

P0 必验：

- 案件工作台。
- 文档上传与解析。
- 案件要素抽取。
- 主体识别。
- 财产线索报告。
- 监控与通知。
- 人工复核。
- 权限与审计。
- 移动 H5 提醒处理。

P0 不验：

- 类案检索完整能力。
- 原生 App。
- 复杂图数据库能力。
- 业务开拓和经营看板。

## 3. 测试矩阵

| 类型 | 内容 |
|---|---|
| 单元测试 | 字段归一化、状态流转、评分计算、权限判断 |
| 集成测试 | 上传到解析、连接器到报告、监控到通知 |
| 契约测试 | API、插件、模型、通知渠道 schema |
| 数据测试 | 来源保留、页码映射、去重、低置信度标记 |
| 安全测试 | 越权访问、敏感数据、模型策略、审计不可绕过 |
| E2E | 真实案件样本完整流程 |
| 可用性测试 | 3-5 名律师真实任务测试 |
| 移动端测试 | 提醒详情、确认、忽略、转任务、深链 |
| 回归测试 | 模型、连接器、模板升级后固定样本集 |

## 4. P0 样本验收集

最低样本：

- 10 份真实 PDF。
- 5 个执行案件样本。
- 2 到 3 个授权数据源。
- 20 条历史或模拟监控事件。
- 5 份人工确认的标准财产线索报告。

## 5. 功能验收

### 5.1 文档解析

通过标准：

- PDF 上传成功并进入解析任务。
- 输出 Markdown、JSON blocks、页码/坐标映射。
- 低置信度内容高亮并进入待校对。
- 原文和解析结果可双向对照。

### 5.2 财产线索报告

通过标准：

- 输入被执行人后可生成报告。
- 每条线索有来源、时间、置信度、评分、建议动作。
- 线索可确认、修改、驳回、转任务。
- 报告不能包含无来源关键结论。

### 5.3 监控通知

通过标准：

- 可配置监控主体和事件类型。
- 新事件能生成监控事件。
- 通知能发送到配置渠道。
- 移动端能确认、忽略、转任务。

### 5.4 权限审计

通过标准：

- 未授权用户不能访问案件。
- L3/L4 数据触发模型策略。
- 上传、查询、报告、导出、复核都有审计记录。

## 6. 客户体验验收

| 场景 | 标准 |
|---|---|
| 律师首次使用 | 30 分钟内完成上传、看报告、处理提醒 |
| 负责人看案件 | 30 秒内说清最新线索、风险、待办 |
| 手机处理提醒 | 3 步内完成确认/忽略/转任务 |
| 线索可信判断 | 能指出来源、时间、下一步动作 |
| 错误反馈 | 能驳回错误线索并写原因 |

门禁：5 名律师中至少 4 名无指导完成 P0 主流程。

## 7. 性能门禁

| 指标 | 目标 |
|---|---|
| 桌面首页核心内容 | 3 秒内可用 |
| 移动提醒详情 | 2 秒内可读 |
| 列表交互 | 100ms 内反馈 |
| 文件上传反馈 | 立即显示任务状态 |
| 长任务 | 1 秒后显示进度或排队状态 |

## 8. 禁止上线条件

- 报告无法回溯来源。
- 模型输出无引用法律结论。
- 用户可越权查看案件。
- 数据源访问绕过授权或平台限制。
- 敏感材料进入不合规外部模型。
- 移动端通知泄露完整敏感信息。
- 审计日志缺失关键操作。

## 9. 验收证据

每次验收需保留：

- 测试样本清单。
- E2E 流程截图或录屏。
- API/插件契约测试结果。
- 安全测试结果。
- 律师可用性测试记录。
- 缺陷列表和修复状态。
- 上线风险结论。

## 10. 交接对象

- 给研发：明确必须补的测试和阻断缺陷。
- 给产品：明确客户验收是否达标。
- 给交付：明确上线风险和回滚条件。
