# 12-P1 办案辅助增强施工文档

## 1. 阶段目标

在 P0 执行案件线索闭环基础上，增加更贴近律师办案过程的辅助能力：类案检索、证据矩阵、文书初稿与质检、庭审笔录摘要。

所有输出必须保持“辅助材料”定位，不能替代律师判断。

## 2. 功能范围

| 编号 | 功能点 | 说明 | 验收 |
|---|---|---|---|
| P1-12-01 | 类案检索 | 基于案由、法院、争议焦点、执行路径检索相似案例 | 每个案例必须说明相似点、差异点、引用来源 |
| P1-12-02 | 裁判倾向摘要 | 聚合同类案例中的支持/不支持因素 | 不得生成无来源的确定性结论 |
| P1-12-03 | 证据矩阵 | 将事实主张、证据、来源页码、证明目的、缺口关联 | 律师可标记已确认、缺证、待补 |
| P1-12-04 | 文书初稿 | 生成执行申请、财产线索说明、情况说明等受控初稿 | 初稿必须带引用和律师复核状态 |
| P1-12-05 | 文书质检 | 检查事实引用、金额、主体、日期、证据编号不一致 | 质检结果可跳回来源 |
| P1-12-06 | 庭审/谈话笔录摘要 | 对合法取得的笔录或录音转写文本进行摘要 | 必须保留原文片段和人工校对状态 |
| P1-12-07 | 证据归类命名 | 按案件要素和证据用途自动建议文件名和分类 | 律师助理可批量确认或修改 |

## 3. 非目标

- 不做自动出具最终法律意见。
- 不做未经授权的法院/案例数据库抓取。
- 不做庭审录音自动获取。
- 不做完全无人审查的文书提交。

## 4. 数据影响

建议新增：

| 实体 | 用途 |
|---|---|
| `similar_cases` | 类案结果、来源、相似度、差异点 |
| `legal_arguments` | 裁判观点、支持因素、反对因素、引用 |
| `evidence_items` | 证据条目、文件、页码、证明目的、状态 |
| `evidence_matrix_rows` | 事实主张与证据的映射 |
| `draft_documents` | 文书初稿、模板、引用、复核状态 |
| `document_quality_checks` | 文书质检问题和修复状态 |
| `transcript_summaries` | 笔录摘要、原文片段、校对状态 |

## 5. API/BFF 影响

建议新增：

```text
POST /api/cases/{case_id}/similar-cases/search
GET  /api/cases/{case_id}/similar-cases
POST /api/cases/{case_id}/evidence-matrix
GET  /api/cases/{case_id}/evidence-matrix
PATCH /api/evidence-items/{evidence_id}
POST /api/cases/{case_id}/draft-documents
GET  /api/draft-documents/{draft_id}
POST /api/draft-documents/{draft_id}/quality-check
POST /api/cases/{case_id}/transcript-summaries
BFF  /bff/cases/{case_id}/case-assistance
```

## 6. 模型与安全策略

- L3/L4 材料默认走私有或本地模型。
- 类案检索来源必须来自授权案例库或内部导入库。
- 文书初稿必须标记“待律师复核”。
- 所有法律观点必须绑定来源，不允许孤立生成。
- 提示词必须防注入，外部材料不得覆盖系统规则。

## 7. 用户体验要求

- 律师看到的是“可用证据、缺失证据、建议补充”，不是技术过程。
- 类案结果必须先解释“为什么相关”，再展示正文摘要。
- 证据矩阵要支持按事实主张、证据状态、来源文件过滤。
- 文书质检问题要能一键定位原始文件、页码或段落。

## 8. 验收标准

- 类案检索结果 100% 带来源、相似点和差异点。
- 证据矩阵中每个事实主张至少能绑定 0-N 个证据，并标记缺口。
- 文书初稿必须包含引用清单和复核状态。
- 文书质检能识别主体、金额、日期、证据编号至少四类不一致。
- 笔录摘要不得丢失人工校对入口。

## 9. 回滚策略

- 类案检索失败时隐藏该模块，不影响 P0 线索报告。
- 文书初稿功能可按模板 feature flag 关闭。
- 证据矩阵可以退回只读展示，保留已录入证据。
- 质检失败时不阻止律师查看或下载原始文书。
