# 02 UX_FLOW：律师客户体验与多端流程

## 1. 设计原则

律师是客户，不是技术用户。界面只表达业务判断，不暴露 OCR、RAG、embedding、模型网关等技术词。

所有关键结论必须回答：

```text
为什么重要？
来源在哪里？
下一步做什么？
```

## 2. 交付形态

| 端 | P0 定位 | 做什么 | 不做什么 |
|---|---|---|---|
| 桌面 Web | 主工作台 | 文档处理、线索报告、复核、监控配置、权限审计 | 不做成移动卡片堆叠的弱功能页 |
| 移动 H5/PWA | 轻操作入口 | 看提醒、看摘要、确认/忽略/转任务、轻量上传 | 不做复杂 PDF 校对和报告编辑 |
| 飞书/企微/邮件 | 通知入口 | 推送事件、深链跳转、催办 | 不承载完整业务流程 |
| 小程序 | P1 候选 | 微信生态客户的轻量入口 | P0 不强制 |
| 原生 App | P2 候选 | 高频移动、离线、拍照扫描、安全管控 | P0 不做 |

## 3. 桌面 Web 信息架构

```text
首页
案件
材料
线索
监控
任务
报告
设置
```

### 3.1 首页

目标：负责人和律师快速知道今天该看什么。

模块：

- 今日新增线索。
- 即将到期事项。
- 待复核报告。
- 监控异常。
- 高价值线索排行。
- 我的任务。

### 3.2 案件详情

页面结构：

```text
案件概览
  - 今日重点
  - 关键期限
  - 最新线索
  - 待复核事项
  - 风险提示

材料
  - 原文件
  - 解析文本
  - 低置信度校对
  - 要素抽取

线索
  - 线索排序
  - 来源与证据
  - 建议动作
  - 核验状态

监控
  - 监控主体
  - 新增事件
  - 推送记录

报告
  - 财产线索报告
  - 案件要素摘要
  - 导出记录
```

## 4. 移动端流程

移动端只做高频轻操作。

### 4.1 提醒处理流程

```text
收到提醒
  -> 打开移动详情页
  -> 查看事件摘要、来源、建议动作
  -> 选择确认/忽略/转任务
  -> 返回处理结果
```

门禁：不超过 3 步。

### 4.2 线索详情页

必须展示：

- 线索标题。
- 重要性等级。
- 来源平台和发现时间。
- 关联主体。
- 建议动作。
- 待核验事项。
- 操作按钮：确认、忽略、转任务、分享给负责人。

### 4.3 移动上传

P0 支持：

- 拍照上传。
- 从微信/企微/飞书文件转入。
- 标记所属案件。
- 上传后提示“正在解析，完成后通知”。

P0 不支持：

- 手机端复杂校对。
- 手机端大报告编辑。
- 手机端插件和权限管理。

## 5. 关键组件

| 组件 | 用途 | 关键字段 |
|---|---|---|
| 案件摘要卡 | 首页和案件列表 | 案件阶段、最新线索、待办数、风险等级 |
| 线索卡片 | 线索列表和移动详情 | 标题、评分、来源、建议动作、复核状态 |
| 来源引用块 | 所有报告 | 来源名称、链接、时间、页码/片段 |
| 复核状态条 | 报告和抽取结果 | 待复核、已确认、已修改、已驳回 |
| 期限提醒 | 案件首页 | 期限类型、剩余天数、来源 |
| 任务按钮组 | 线索和提醒 | 确认、忽略、转任务、分派 |

## 6. 状态与文案

| 技术状态 | 律师可见文案 |
|---|---|
| parse_pending | 材料排队处理中 |
| parse_running | 正在整理材料 |
| parse_low_confidence | 有内容需要校对 |
| extract_done | 要素摘要已生成 |
| report_draft | 报告待复核 |
| report_confirmed | 报告已确认 |
| connector_failed | 数据源暂时不可用，可稍后重试或人工补录 |
| monitor_event_new | 发现新动态 |

## 7. 交互规则

- 重要操作必须有撤销或二次确认。
- 低置信度内容必须高亮，不默认进入最终结论。
- 用户离开页面前保留草稿状态。
- 所有列表支持按风险、时间、价值、状态筛选。
- 移动端表格转摘要卡，不强行压缩成横向表格。
- 通知点击必须恢复到对应案件、线索或任务。

## 8. 可用性验收

| 场景 | 标准 |
|---|---|
| 新律师使用 | 30 分钟内完成上传、看报告、处理提醒 |
| 负责人查看案件 | 30 秒内说清最新风险和待办 |
| 手机处理提醒 | 3 步内确认/忽略/转任务 |
| 线索可信判断 | 用户能指出来源、时间和建议动作 |
| 错误反馈 | 用户能驳回并填写原因 |

## 9. 交接对象

- 给前端：作为页面、组件和状态文案的设计依据。
- 给 BFF：作为多端聚合数据的字段裁剪依据。
- 给 QA：作为可用性测试脚本依据。
