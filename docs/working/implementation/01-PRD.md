# 01 PRD：执行案件财产线索与动态监控工作台

## 1. 产品定位

本产品面向律师团队，第一阶段帮助律师围绕执行案件完成材料整理、主体识别、财产线索发现、动态监控、报告复核和任务跟进。

一句话目标：

```text
让律师打开一个案件后，30 秒内看到最重要的线索、风险、来源和下一步动作。
```

## 2. 目标用户

| 用户 | 主要任务 | 成功体验 |
|---|---|---|
| 律所负责人 | 看案件风险、线索价值、团队进度 | 一眼知道哪些案件值得投入和催办 |
| 承办律师 | 核验线索、判断动作、出具报告 | 快速获得可追溯、可复核的线索报告 |
| 律师助理 | 上传材料、整理文档、跟踪提醒 | 少录入、少查重、少重复整理 |
| IT/管理员 | 配数据源、控权限、查审计 | 系统可控、可维护、可追责 |
| 法律业务专家 | 定义模板、复核质量、沉淀规则 | 经验能变成模板、评分和反馈集 |

## 3. P0 MVP 范围

### 必须做

- 案件工作台：案件列表、案件详情、今日重点、待复核事项。
- 文档中心：上传 PDF，解析为 Markdown/JSON，支持原文页码/片段追溯。
- 案件要素抽取：案号、法院、案由、当事人、金额、期限、执行依据。
- 主体识别：企业/自然人主体画像、曾用名、统一社会信用代码、关联主体。
- 财产线索报告：股权、执行、拍卖、知识产权、招投标、关联主体等线索。
- 线索评分：可执行性、价值规模、新鲜度、可信度、关联强度、行动成本。
- 动态监控：重点主体监控、字段 Diff、事件提醒、转任务。
- 通知入口：飞书/企业微信/邮件/站内通知，支持移动端深链。
- 人工复核：确认、修改、驳回、转任务、标记有用/无用。
- 权限与审计：上传、查询、模型调用、报告输出、复核全链路留痕。

### 应该做

- 移动 H5 提醒详情页。
- 低置信度内容高亮与校对状态。
- 线索报告导出为 Word/PDF 的基础能力。
- 数据源失败告警和人工补录入口。

### 可以延后

- 类案检索和裁判倾向分析。
- 证据矩阵和文书初稿。
- 庭审录音转写摘要。
- 业务开拓线索和政策合规提示。
- 私有知识图谱和律师反馈蒸馏。
- 原生 App 或跨平台 App。

### 明确不做

- 不做全能法律 AI。
- 不替代律师作最终法律判断。
- 不自动查询非公开房产、车辆、银行账户。
- 不绕过验证码、登录限制、平台风控、付费墙。
- 不生成无来源、无引用、无审计的法律结论。

## 4. 核心用户旅程

### 4.1 上传材料到案件摘要

1. 助理创建案件并上传判决书、合同、证据材料。
2. 系统解析 PDF，输出可读 Markdown、结构化 JSON、原文坐标。
3. 系统抽取案号、法院、案由、金额、期限、执行依据。
4. 低置信度内容进入待校对列表。
5. 承办律师确认要素摘要。

验收：新案件上传后，10 分钟内看到第一版可读材料或要素摘要。

### 4.2 被执行人到财产线索报告

1. 律师输入被执行人名称或统一社会信用代码。
2. 系统进行主体识别与消歧。
3. 系统调用授权数据源连接器。
4. 系统抽取并排序财产线索。
5. 律师查看线索来源、重要性和建议动作。
6. 律师确认、驳回或转任务。

验收：每条线索必须有来源、时间、置信度、建议动作和待核验事项。

### 4.3 监控提醒到任务

1. 律师配置重点主体监控。
2. 系统定时查询数据源并比较快照。
3. 系统识别新增执行、拍卖、股权冻结等事件。
4. 系统通过通知渠道推送。
5. 律师在手机端查看、确认/忽略/转任务。

验收：手机端 3 步内完成查看提醒、确认/忽略、转任务。

## 5. 页面与信息架构

P0 主导航：

```text
首页 / 案件 / 材料 / 线索 / 监控 / 任务 / 报告 / 设置
```

案件详情页核心区域：

- 今日重点。
- 关键期限。
- 最新线索。
- 待复核事项。
- 风险提示。
- 材料解析状态。
- 监控事件。

移动端只承载轻操作：

- 今日提醒。
- 案件动态。
- 线索详情。
- 确认/忽略/转任务。
- 查看报告摘要。
- 拍照或上传材料。

## 6. 业务指标

| 指标 | P0 目标 |
|---|---|
| 材料整理耗时 | 下降 50%-80% |
| 初步财产线索报告 | 从半天/一天降到几十分钟 |
| 线索可追溯 | 100% 线索有来源和时间 |
| 移动处理效率 | 3 步内处理提醒 |
| 学习成本 | 新律师 30 分钟内掌握 P0 主流程 |
| 复核闭环 | 每个报告都有复核状态 |
| 噪声反馈 | 每条提醒可标记不重要/重复/已处理 |

## 7. 验收场景

1. 助理上传判决书 PDF，系统生成可读 Markdown，并标出待校对内容。
2. 承办律师输入被执行人，系统生成财产线索报告，并能点回来源。
3. 律师在手机上收到新增拍卖提醒，能 3 步内确认并转任务。
4. 负责人打开案件首页，30 秒内看懂最新线索、风险和待办。
5. 律师驳回一条错误线索，系统记录原因并进入反馈集。

## 8. 交接对象

- 给 UX：依据本 PRD 设计桌面和移动流程。
- 给后端：依据本 PRD 建案件、主体、线索、监控、任务领域模型。
- 给 AI：依据本 PRD 实现文档解析、要素抽取、线索评分、报告生成。
- 给 QA：依据本 PRD 建验收用例和真实律师可用性测试。
