# 09 RUNBOOK：部署、运维与故障处理手册

## 1. 目标

确保 P0 试点上线后，连接器、文档解析、模型调用、监控通知和权限审计出现问题时有明确处理路径、降级策略和回滚方案。

## 2. 运行组件

| 组件 | 说明 |
|---|---|
| Web/BFF | 桌面 Web、移动 H5、聚合接口 |
| API 服务 | 案件、文件、主体、线索、监控、报告 |
| Worker | OCR、抽取、连接器、报告生成、通知 |
| PostgreSQL | 主业务库 |
| 对象存储 | 原文件、解析结果、原始响应引用 |
| 搜索/向量索引 | 文本检索和语义检索 |
| Redis/Queue | 缓存和异步任务 |
| 模型网关 | 模型路由、数据策略、调用记录 |
| 通知渠道 | 飞书、企微、邮件、站内通知 |

## 3. 部署前检查

- 环境变量完整。
- 数据库迁移完成。
- 对象存储桶可访问。
- 队列和 Worker 正常。
- 插件 contract test 通过。
- 数据源授权有效。
- 模型策略配置完成。
- 通知机器人可发送测试消息。
- 审计日志写入正常。
- 回滚版本可用。

## 4. 常见故障处理

### 4.1 文件上传失败

现象：用户上传文件失败或长时间无响应。

排查：

1. 检查文件大小和格式限制。
2. 检查对象存储可用性。
3. 检查 API 错误日志。
4. 检查用户权限和案件状态。

降级：允许用户稍后重试或由管理员代传。

### 4.2 文档解析失败

现象：parse_status 为 failed 或长时间 running。

排查：

1. 检查 Worker 是否存活。
2. 检查 OCR/解析器插件日志。
3. 检查原文件是否损坏。
4. 检查对象存储读取权限。

降级：标记为“人工整理”，保留原文件，允许人工上传文本。

### 4.3 数据连接器失败

现象：生成线索报告时数据源不可用。

排查：

1. 检查授权是否过期。
2. 检查 rate limit。
3. 检查插件 contract test。
4. 检查外部服务状态。

降级：关闭对应 connector feature flag，报告中标记该数据源暂不可用，允许人工补录。

### 4.4 模型调用被拦截

现象：模型网关返回 DATA_POLICY_BLOCKED。

处理：

1. 确认材料数据等级。
2. 确认模型供应商策略。
3. 如确需处理，走脱敏或私有模型路径。
4. 不得绕过策略网关直接调用模型。

### 4.5 监控通知未发送

排查：

1. 检查 monitor job 是否执行。
2. 检查事件是否生成。
3. 检查通知渠道配置。
4. 检查机器人 webhook 或邮件服务。

降级：站内通知保底，管理员手动导出事件列表。

### 4.6 权限异常

现象：用户看不到案件或看到不该看的案件。

处理：

1. 立即冻结相关用户会话。
2. 检查角色、案件授权、租户 ID。
3. 查 audit_logs 确认影响范围。
4. 如存在越权泄露，进入安全事件流程。

## 5. 回滚策略

| 对象 | 回滚方式 |
|---|---|
| Web/BFF | 回滚前端版本或关闭新入口 |
| API | 回滚服务镜像，保持数据库兼容 |
| 插件 | 关闭 feature flag，回退旧版本 |
| 模型 | 切回默认供应商或禁用外部模型 |
| 解析器 | 切回上一版本解析器 |
| 通知 | 关闭外部通知，保留站内通知 |
| 数据库迁移 | 仅允许可逆迁移；不可逆迁移需备份恢复方案 |

## 6. 告警指标

必须监控：

- API 5xx 错误率。
- 文件上传失败率。
- 文档解析失败率和平均耗时。
- 连接器失败率。
- 模型调用失败率和成本。
- 监控任务延迟。
- 通知发送失败率。
- 权限拒绝异常峰值。
- Worker 队列积压。

## 7. 日常巡检

每日：

- 查看失败任务。
- 查看连接器错误。
- 查看通知失败。
- 查看高风险审计记录。

每周：

- 抽查报告来源引用。
- 复盘律师驳回原因。
- 检查插件版本和授权状态。
- 检查存储和模型成本。

每月：

- 回顾可用性指标。
- 清理过期原始响应。
- 演练一次关键插件回滚。
- 更新 QA 回归样本。

## 8. 安全事件流程

触发条件：

- 越权访问案件。
- 敏感数据进入不合规模型。
- 通知泄露敏感信息。
- 审计日志缺失或异常删除。

流程：

1. 立即冻结相关功能或用户。
2. 保留日志和证据。
3. 评估影响案件和用户。
4. 通知负责人。
5. 修复并复测。
6. 输出复盘和防回归项。

## 9. 上线后观察窗口

试点上线后 7 天为重点观察窗口。

每天检查：

- 是否有阻断性缺陷。
- 律师是否能完成 P0 主流程。
- 推送是否过多或过少。
- 报告是否有无来源结论。
- 是否出现权限或数据策略异常。

## 10. 交接对象

- 给运维：部署、告警和故障响应。
- 给研发：定位和回滚路径。
- 给产品：客户影响说明。
- 给安全/管理员：审计和事件处理。
