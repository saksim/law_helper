# 14-P2 知识沉淀与增长施工文档

## 1. 阶段目标

P2 的知识与增长能力用于把律师团队在办案中形成的经验、反馈、客户行业信息和政策变化沉淀为可复用资产，并支持业务开拓和团队经营。

核心结果：

- 私有知识图谱沉淀案件、主体、证据、观点、关系。
- 律师反馈进入模型评估和策略迭代。
- 业务开拓情报和行业政策监控形成可复核线索。
- 团队经营看板展示效率、质量、回款和成本。

## 2. 功能范围

| 编号 | 功能点 | 说明 | 验收 |
|---|---|---|---|
| P2-14-01 | 私有知识图谱 | 连接案件、主体、关系、证据、观点、线索和结果 | 任一知识节点可追溯来源和授权范围 |
| P2-14-02 | 律师反馈蒸馏 | 从确认、驳回、修改、行动结果中沉淀规则和样本 | 反馈可进入评估集和策略候选 |
| P2-14-03 | 模型评估流水线 | 固定样本集、评分、回归比较、版本记录 | 模型或提示词升级前后可比较 |
| P2-14-04 | 业务开拓情报 | 监控新增注册、涉诉、招投标、政策风险企业 | 输出潜在客户线索和推荐跟进原因 |
| P2-14-05 | 行业政策监控 | 按行业、地区、客户类型监控政策和合规变化 | 每条政策提示有来源、影响对象和建议动作 |
| P2-14-06 | 客户合规提示 | 面向客户生成受控提示，由律师审核后发送 | 不允许系统自动对外发送法律意见 |
| P2-14-07 | 团队经营看板 | 案件效率、线索价值、回款进展、律师负载、成本 | 团队负责人可按时间和团队查看 |

## 3. 非目标

- 不把系统输出作为直接对外法律意见。
- 不自动联系潜在客户。
- 不构建无法追溯来源的黑箱知识库。
- 不用客户敏感材料训练外部模型。

## 4. 知识对象模型

建议核心对象：

| 对象 | 说明 |
|---|---|
| `knowledge_nodes` | 案件、主体、证据、观点、政策、客户、行业等节点 |
| `knowledge_edges` | 股权、关联、证明、支持、反驳、影响、相似等关系 |
| `feedback_insights` | 从律师反馈蒸馏出的规则、偏好和质量问题 |
| `evaluation_runs` | 模型、提示词、模板版本的评估结果 |
| `business_leads` | 潜在客户或业务机会 |
| `policy_alerts` | 行业政策和合规提示 |
| `management_metrics` | 团队经营指标 |

## 6. 数据与合规要求

- 知识节点必须带来源、敏感等级、授权范围、创建方式。
- 业务开拓情报只能使用合法授权或公开允许使用的数据。
- 客户合规提示必须由律师审核后才能对外发送。
- 模型评估样本必须脱敏或走私有模型策略。
- 经营看板只展示团队负责人有权查看的数据。

## 7. 用户体验要求

- 知识图谱不作为炫技图，而服务于“为什么相关、下一步做什么”。
- 业务线索必须解释触发原因、潜在价值、跟进风险。
- 政策提示必须翻译为律师和客户都能理解的影响说明。
- 经营看板应优先展示异常和趋势，而不是堆指标。

## 8. 验收标准

- 知识节点和边 100% 可追溯来源。
- 每次模型或提示词升级前后都有评估记录。
- 业务开拓线索必须可被律师标记有效、无效、已跟进。
- 政策提示必须包含来源、影响对象、建议动作和律师审核状态。
- 经营看板至少包含案件周期、线索确认率、报告驳回率、回款状态、成本趋势。

## 9. 回滚策略

- 知识图谱失败时，退回搜索和列表视图。
- 业务开拓情报可按数据源或行业关闭。
- 政策提示可只保留内部提醒，不对外生成客户提示。
- 模型评估流水线失败时禁止自动推广新版本。
