# 律师团队 AI 项目会议沟通稿 V4：律所负责人视角与 IT 负责人视角

生成日期：2026-06-01

## 0. 核心结论

这件事能干，而且值得干。

但它不应该被定义为“AI 聊天工具项目”，而应该被定义为：

```text
法律案件数据平台项目
```

更具体地说：

```text
第一阶段做执行案件财产线索与动态监控工作台。
长期方向是法律案件作战室 + 执行财产线索引擎 + 法律情报监控平台。
```

第一阶段不要一上来做全平台，但架构必须按平台级能力预留。否则 PDF 解析、财产线索、主体监控、类案检索、证据矩阵、文书生成、案件复盘都会变成互不相通的小工具，后续无法复用。

推荐策略：

```text
单点切入，平台沉淀。
场景化落地，平台化设计。
```

## 1. 给律所负责人的话术

### 1.1 这事能不能干

能干，而且最先应该解决执行案件和日常办案中最消耗人力的部分：

- 材料整理。
- 财产线索挖掘。
- 主体动态监控。
- 案件要素抽取。
- 类案辅助。

这不是让 AI 替代律师，也不是承诺 AI 自动打赢官司，而是把律师团队现在最耗时间、最重复、最容易遗漏的信息处理工作系统化。

### 1.2 第一阶段干到什么程度

第一阶段建议目标：

```text
PDF/证据材料自动整理
+ 被执行人财产线索报告
+ 重点主体动态监控
+ 案件要素抽取
```

律师实际看到的系统应该是：

- 上传判决书、合同、证据 PDF，系统自动转成可编辑、可检索文本。
- 输入被执行人，系统自动汇总公开执行信息、工商股权、司法拍卖、关联主体。
- 对重点公司或个人持续监控，一有新增被执行、拍卖、股权变更、失信限高等事件就提醒。
- 从起诉状、判决书、裁定书中自动抽取案由、金额、期限、上诉期、执行依据等要素。
- 系统生成报告，但最终由律师复核。

### 1.3 能带来的收益

对律所来说，核心收益不是“用了 AI”，而是：

```text
降低人力成本，提高线索发现率，减少信息遗漏，提高执行案件回款机会。
```

| 场景 | 现在的成本 | AI 后的目标 |
|---|---|---|
| PDF/证据整理 | 律师助理手工看、改名、摘录 | 自动 OCR、转 Markdown、归类命名，律师校对 |
| 执行财产线索 | 人工查企查查、执行网、拍卖网 | 自动汇总股权、拍卖、执行、关联主体线索 |
| 对手方监控 | 靠人定期刷网页 | 新增执行、拍卖、股权变更自动提醒 |
| 案件要素抽取 | 人工从判决书/起诉状摘字段 | 自动抽案由、金额、期限、上诉期、执行依据 |
| 类案检索 | 初级律师花数小时找案例 | 自动召回有利/不利案例，律师判断能否引用 |

可预期的第一阶段收益：

- 文档整理时间下降 50%-80%。
- 初步财产线索报告从半天或一天缩短到几十分钟。
- 对重点主体的动态监控从人工检查变成自动提醒。
- 初级律师和助理的产出更标准。
- 负责人复核从“从零看材料”变成“看系统整理后的结构化报告”。
- 执行案件中更早发现可执行资产和关联主体线索。

### 1.4 不能承诺什么

必须提前讲清楚：

- AI 不能替代律师判断。
- AI 不能保证胜诉。
- AI 不能保证查到所有财产。
- AI 不能自动查询非公开房产、车辆、银行账户。
- AI 不能绕过验证码、登录限制、平台风控或付费墙。
- AI 生成的报告不能直接作为最终法律意见对外出具。

系统的合理定位是：

```text
律师的办案辅助系统，不是自动办案系统。
```

### 1.5 成本在哪里

负责人需要知道，成本不只是买 AI 账号。

真实成本包括：

1. 技术开发成本：文档解析、数据源、监控、前端、后端、AI 服务、审计。
2. 数据成本：企查查、天眼查、法律数据库、商业 API 等授权。
3. 模型成本：OCR、Embedding、Rerank、大模型调用或私有化部署。
4. 运维成本：网站结构变更、接口异常、任务失败、监控告警。
5. 业务共创成本：律师要提供样本、校验结果、定义线索价值。

建议投入节奏：

```text
验证版：6-8 周，4-6 人月，只能演示
试点版：10-14 周，12-18 人月，可以内部真实试用
生产增强版：4-6 个月，30-45 人月，可稳定服务团队
平台产品版：9-12 个月，90-150 人月，适合多团队复制
```

当前建议选择：

```text
试点版：10-14 周，约 12-18 人月。
```

### 1.6 给负责人的定调

建议对负责人这样说：

```text
这事能干，但我们不建议一上来做全能法律 AI。第一期先围绕执行案件，把材料整理、财产线索、动态监控做成可用工具。它的价值是降低人工检索和整理成本，提高线索发现率，减少执行案件中因信息滞后造成的机会损失。
```

## 2. 给 IT 负责人的话术

### 2.1 这事的技术本质

这不是一个 Prompt 工程项目，也不是简单接一个大模型 API。

它本质上是一个多模块系统：

```text
Document Pipeline
+ External Data Connector
+ Entity Resolution
+ Asset Clue Engine
+ Monitoring & Notification
+ Legal Extraction/RAG
+ Audit & Permission
```

第一阶段不是完整平台，但底层必须预留平台边界。

### 2.2 第一阶段系统模块

至少需要以下模块：

1. 文档解析中心  
   PDF、OCR、表格、版面、Markdown、JSON、原文坐标映射。

2. 外部数据连接器  
   执行信息、工商信息、司法拍卖、商业 API。

3. 主体识别与消歧  
   企业名称、曾用名、统一社会信用代码、法定代表人、股东、关联企业。

4. 财产线索引擎  
   股权、司法拍卖、知识产权、招投标、应收账款、关联主体。

5. 监控调度系统  
   定时查询、网页快照、字段 Diff、语义 Diff、事件分类。

6. AI 抽取与报告生成  
   案件要素抽取、证据归类、财产线索报告、类案摘要。

7. 权限与审计  
   谁查了谁、上传了什么材料、调用了哪个模型、输出了什么报告。

### 2.3 技术难点排序

技术难点不在“选哪个大模型”。

真正的难点排序大致是：

```text
数据源稳定性 > PDF 解析质量 > 主体消歧 > 法律语义抽取 > 大模型生成
```

具体风险：

- 数据源可能有验证码、登录限制、反爬策略。
- 商业平台可能禁止未授权抓取。
- PDF 可能是低清扫描件、多栏、表格、手写批注。
- 企业主体可能有曾用名、同名公司、关联公司。
- AI 生成报告可能幻觉或遗漏来源。
- 涉及个人信息、商业秘密和客户案件材料，必须做权限、脱敏、审计。

### 2.4 推荐技术路线

建议第一期采用：

- 后端：Python FastAPI 或 Node/NestJS；AI 任务建议 Python。
- 异步任务：Celery/RQ/Temporal，MVP 可 Celery。
- 数据库：PostgreSQL。
- 向量库：pgvector 或 Qdrant。
- 全文检索：OpenSearch/Elasticsearch。
- 对象存储：MinIO/S3 兼容存储。
- OCR/文档解析：PaddleOCR/PP-StructureV3 + MinerU/Marker/Docling 对比。
- 浏览器自动化：Playwright，但只用于合规、低频、可审计场景。
- 推送：飞书、企业微信、邮件。
- 模型：国内合规云模型或私有化模型作为主力。

### 2.5 给 IT 的定调

建议对 IT 负责人这样说：

```text
这不是简单接一个大模型 API。第一期要搭一个轻量平台底座，包括文档解析、数据连接器、主体识别、监控调度、AI 抽取、报告生成和审计。模型可以替换，数据结构和工作流不能乱。国内模型应作为案件材料处理主力，美国模型只建议处理公开或脱敏低敏数据。
```

## 3. 使用 AI VS 不使用 AI

不是“用了 AI 就先进，不用 AI 就落后”。

正确判断是：

```text
规则、API、数据库负责确定性任务。
AI 负责非结构化理解、摘要、归类、推理辅助和报告生成。
```

| 方案 | 能做什么 | 做不到什么 | 适合情况 |
|---|---|---|---|
| 不用 AI，只做传统系统 | 表单、流程、数据库、API 查询、监控 | 很难处理非结构化 PDF、判决书、聊天记录、复杂摘要 | 数据高度结构化、规则明确 |
| 使用 AI | OCR 后理解、要素抽取、摘要、归类、类案语义检索、报告生成 | 不能无监督给最终法律意见，不能保证无幻觉 | 法律材料复杂、非结构化材料多 |
| AI + 传统系统结合 | 结构化任务走规则/API，非结构化任务走 AI | 成本和工程复杂度更高 | 最推荐 |

推荐方案：

```text
AI + 传统系统结合。
```

示例：

- 查企业工商信息：优先 API，不靠大模型。
- 判断 PDF 里哪段是“本院认为”：AI/版面模型有价值。
- 生成财产线索报告：AI 有价值。
- 判断是否申请冻结股权：律师决策。
- 监控网页变化：传统调度 + AI 语义判断结合。

## 4. 国内 AI VS 美国 AI

### 4.1 总体结论

法律案件材料、客户合同、身份证号、银行流水、商业秘密，第一选择应是国内合规云或私有化模型。

美国 AI 可以作为高能力工具，但不应直接处理未脱敏敏感案件材料。

建议策略：

```text
国内模型处理案件原始材料。
美国模型处理公开数据、脱敏数据、低敏分析、技术评测和能力增强。
```

### 4.2 对比表

| 维度 | 国内 AI | 美国 AI |
|---|---|---|
| 数据合规 | 更容易满足境内处理、私有化、审计要求 | 可能涉及数据出境，需要额外合规评估 |
| 中文法律场景 | 对中文、国内语境适配较好 | 通用推理强，但中国法律细节仍需 RAG 支撑 |
| 模型能力 | 已足够处理 OCR 后抽取、摘要、报告、分类等大部分任务 | 顶级模型在复杂推理、长上下文、多步规划上通常更强 |
| 稳定接入 | 国内部署和采购更顺 | 可能受网络、采购、合规、访问策略影响 |
| 成本 | 可控，私有化可谈 | 高能力模型成本较高 |
| 敏感材料处理 | 更适合 | 不建议直接上传原始敏感材料 |
| 最佳用法 | 主力处理案件材料 | 处理脱敏、公开、低敏任务或作为评测/增强模型 |

### 4.3 数据分级策略

| 数据等级 | 示例 | 模型策略 |
|---|---|---|
| L0 公开数据 | 法条、公开案例、公开政策 | 国内/美国 AI 都可用 |
| L1 公开企业信息 | 工商、拍卖、公开执行信息 | 优先国内，可用美国做脱敏分析 |
| L2 内部案件摘要 | 去客户名后的案情摘要 | 可按合规要求选择 |
| L3 案件原始材料 | 合同、证据、聊天记录 | 国内合规云/私有化优先 |
| L4 高敏材料 | 身份证、流水、商业秘密 | 私有化或本地处理，不进外部模型 |

### 4.4 关键提醒

即使某些海外模型服务说明企业数据默认不用于训练，也不等于可以随意上传中国律所案件材料。

原因是风险不只包括“是否训练模型”，还包括：

- 数据出境。
- 律师保密义务。
- 个人信息保护。
- 客户商业秘密。
- 客户委托协议中的保密要求。
- 律所内部合规要求。

因此：

```text
模型隐私政策不是唯一判断标准。
数据类型、部署位置、客户授权、审计机制同样重要。
```

## 5. 最终落地形态

第一阶段建议落地成：

```text
执行案件财产线索与动态监控工作台
```

第一阶段包括：

- 文档上传。
- PDF 转 Markdown。
- 案件要素抽取。
- 被执行人主体识别。
- 财产线索报告。
- 关联主体图谱。
- 重点主体监控。
- 飞书/邮件/企业微信推送。
- 律师复核。
- 报告归档。

第二阶段扩展：

- 类案检索。
- 执行相关裁判倾向。
- 证据矩阵。
- 文书初稿。
- 庭审笔录摘要。

第三阶段扩展：

- 业务开拓线索。
- 行业政策监控。
- 客户合规提示。
- 案件复盘知识库。
- 团队经营看板。

## 6. 如果只做单点，会有什么问题

### 6.1 只做 PDF 转 Markdown

短期收益：

- 能省整理时间。

问题：

- 不能形成案件线索。
- 解析结果没有进入案件知识库。
- 后续还要重复建设上传、权限、存储、审计。
- 无法沉淀为团队资产。

### 6.2 只做爬虫

短期收益：

- 能查一些信息。

问题：

- 合规和稳定性风险高。
- 数据无法和案件、主体、证据、复盘打通。
- 网站结构一变就失效。
- 无法形成可复核的办案报告。

### 6.3 只做 ChatGPT 法律助手

短期收益：

- 演示效果好。

问题：

- 真实案件不敢直接用。
- 没有数据源。
- 没有引用。
- 没有审计。
- 容易产生幻觉和责任风险。

### 6.4 正确路线

单点可以做验证，但不能作为最终路线。

正确路线是：

```text
单点切入，平台沉淀。
```

第一期选执行案件，是因为执行案件 ROI 最清晰：

```text
被执行人财产线索越早发现，越可能影响回款。
```

## 7. 建议会议收敛问题

下一次和对方会议，不建议开放讨论所有 AI 能力。

建议把问题收敛成一句：

```text
是否先用 10-14 周，做一个“执行案件财产线索与动态监控工作台”试点？
```

围绕这句话，再确认：

1. 执行案件占比多少？
2. 现在每个执行案件查财产线索平均花多少小时？
3. 最常查的 3 个平台是什么？
4. 是否已有企查查、天眼查、法律数据库等账号或 API 权限？
5. 是否愿意采购商业 API？
6. 是否接受第一版不覆盖非公开不动产、车辆、银行账户查询？
7. 推送希望走飞书、企业微信、邮件，还是系统内通知？
8. 是否能提供 10 份真实 PDF 样本做解析评估？
9. 是否能提供 5 个执行案件样本做财产线索报告试点？
10. 是否有私有化部署或不得出网要求？

```text
这不是简单接一个大模型 API。第一期要搭一个轻量平台底座，包括文档解析、数据连接器、主体识别、监控调度、AI 抽取、报告生成和审计。模型可以替换，数据结构和工作流不能乱。国内模型应作为案件材料处理主力，美国模型只建议处理公开或脱敏低敏数据。
```

```text

先打通数据和工作流，再谈模型优化和知识沉淀。
```
