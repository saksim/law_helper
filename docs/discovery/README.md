# 探讨层

这里放“为什么这么做”的材料。它们用于形成判断、保存论证链路，但不等同于当前对外承诺，也不等同于发布包。

新增这一层的原因是：本项目有大量需求对齐、方案推演、成本估算、技术路线和会议话术材料。它们不适合放进 `latest/`，因为不是当前稳定使用手册；也不适合直接归入 `archive/`，因为它们仍然解释了当前方案为什么会形成。

## 子目录

- [proposals/](proposals/README.md)：方案、架构、成本、需求对齐等论证材料。
- [meeting-prep/](meeting-prep/README.md)：会议话术、沟通脚本和准备材料。

## 使用规则

- 探讨材料可以有版本号和过程痕迹。
- 一旦某个探讨结论进入当前迭代，应在 `working/` 中形成可执行版本。
- 一旦某个结论被发布，应在发布包 README 中说明来源关系。
- 如果探讨材料被完全废弃，仍可留在这里，但应在文件名或 README 中标注 `superseded`。
